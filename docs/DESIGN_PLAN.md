## 1. 审查结论

在电脑（1366×860）和手机（375×812、360×740）上实际运行并逐个展厅点测。

### 已修复的缺陷

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 每个页面右边缘都有一条灰色阴影 | 关闭状态的目录抽屉在屏幕外，但 `box-shadow` 漏进页面 | 阴影只在打开时出现 |
| 目录抽屉关闭时，键盘 Tab 仍会进入里面的按钮 | 只设了 `aria-hidden` | 关闭时设 `inert`；打开时焦点进抽屉，Esc 关闭后焦点回到按钮 |
| 国内网络下首屏可能长时间白屏 | `styles.css` 第一行 `@import` Google Fonts，阻塞渲染 | 改为非阻塞加载；加载失败直接用宋体 / 苹方 |
| 换事件、换照片时整页闪一下，焦点丢失 | 每次都重绘整个场景并重播入场动画 | 同展厅内切换不重播动画，焦点留在原按钮 |
| 手机上点「下一段回忆」后，新展品在屏幕外 | 按钮在文字下方，展柜在上方 | 切换后自动把展柜带回视野 |
| 手机端底部导航只出现在页面最底 | 小屏 CSS 把它改成了文档流 | 手机端也贴底常驻（含 iPhone 安全区） |
| 只有一张图时也显示左右箭头 | — | 多于一张才显示 |
| 照片一律裁成 4:3 | `object-fit: cover` | 完整显示照片，空白处用同图柔焦填充；可逐张改为裁切 |
| 打开信封是瞬间切换 | 原 CSS 写了 `.is-opening` 但 JS 没用 | 先掀开封口、信纸探出，再展开全文 |
| 离开终厅再回来，信还是打开的 | 状态未重置 | 每次进入终厅都从信封开始 |
| 图片路径写错显示破图 | — | 自动换成占位插画 |

## 2. 从真实素材倒推的设计判断

读完《我们的故事_时间线与逻辑梳理》和《照片归档清单》后，原设计有三处和素材对不上：

| 素材的实际情况 | 原设计 | 新设计 |
| --- | --- | --- |
| 约 35 个时间节点，分成 4 个阶段 | 一条 6 个节点的横轴 | **篇章标签 + 篇章内节点**，每个篇章有一句导语 |
| 2024 年上半年几乎全是**微信聊天截图**（竖长 PNG） | 4:3 横框裁切，截图会被切得只剩中间一段 | **聊天截图组件**：放进柔和的手机外框，只露出开头，点开看全文（可滚动） |
| 2025 年 12 月以后是**拍立得相册内页翻拍**，正面一张、背面手写一张 | 无 | **拍立得组件**：一页可 3D 翻面的相册纸，背面手写原话另外摘成引文 |
| 北戴河出现三次（写字 → 通话 → 一起去） | 地点与时间线互不相关 | **地点 ↔ 时间线互链**：地点详情列出“在这里发生过”的回忆，点击跳到那一天；同一地点去过多次时光点上有 ×N |
| 有明确的相识日和纪念日 | 无 | 入口和大厅显示“我们相识的第 N 天”（填 `since` 才出现） |
| 有很多值得保留的原话（“鸟很远，但风景很好”） | 无 | 事件可加 `quote`，展示为引文 |
| 纪念日、生日、录取等重要日子 | 所有节点一样 | `highlight: true`：节点带芍药色点和 ❀，展柜标“重要的日子” |

## 3. 各展厅的交互设计

### 序厅（intro）
保持原样。新增一行“我们相识的第 N 天”，放在开场文字和「开启参观」按钮之间，数字用衬线大字。

### 中央大厅（foyer）
三个展厅卡片下方各加一行数量（“35 件时间展品 / 10 个地点 / 1 封信”），让她知道里面有多少东西；底部签名行改为“相识第 N 天 · 展览仍在更新”。

### 时间长廊（timeline）—— 主展厅

```
[篇章标签：在聊天里慢慢靠近 | 从第一次见面到共同的小家 | 一起过日子… | 继续见面…]   ← 横向可滑
 篇章导语一句
 ●──────●──────●❀─────●        ← 本篇章内的节点（日期 + 标题），当前节点居中
┌──────────────┐   01
│  展品舞台     │   2024.09.26 · ❀ 重要的日子
│ 照片/截图/拍立得│   正式恋爱纪念日
└──────────────┘   短句 / 故事 / “原话引文”
 说明文字            [←] [下一段回忆 →]  ⌖ 郑州
 ARCHIVE 04/35  ← →
 [缩略图条]
```

- **展品舞台**按媒体类型自动切换：普通照片（完整显示 + 柔焦底）、聊天截图（手机框）、拍立得（翻面按钮）。电脑上舞台 4:3，手机上 1:1（横竖照片都只留很窄的边）。
- **切换方式**：点节点 / 点篇章标签（跳到该篇章第一件）/ 「下一段回忆」/ 键盘左右键；同一件展品的照片用缩略图条、左右箭头或**手机左右滑动**。
- 最后一件展品的按钮变成「去足迹展厅 →」，引导走向下一个展厅。
- 点舞台打开**灯箱**：可左右切换同一件展品的全部照片（拍立得背面自动作为下一张），手机可滑动，键盘左右键，Esc 关闭；相邻照片预加载。

### 足迹展厅（places）
保留「回忆星图」（不是真实地图，界面已写明）。光点下方显示地名；去过多次的地方有 ×N 角标。详情卡新增“在这里发生过 · N 段回忆”列表，点击跳到时间长廊对应事件；时间长廊里的 ⌖ 地点链接也能反向跳回。手机上点光点后，详情卡会自动滚进视野。封面可点开看这个地点的全部照片。

### 终厅（letter）
信封先掀开封口、信纸探出，约 0.9 秒后展开全文；减弱动画模式下直接展开。信纸支持 `date` 落款日期。**信的内容只能由你本人写**，当前私密样板里只留了占位。

## 4. 内容维护与隐私方案

### 已实现的工作流（详见 `docs/CONTENT_GUIDE.md`）

```
本地照片归档（2024/2025/2026 文件夹 + 照片归档清单.csv）
        │  python3 tools/prepare_photos.py      ← macOS 自带 sips，无需安装
        ▼
site/private/photos/…   压缩（259MB → 68MB）、删除 EXIF/GPS
site/private/photo-index.json   每张图的日期、事件、网页路径、横竖
        │  写 / 让 Codex 生成
        ▼
site/private/content.js   真实内容（与 content.js 同结构）
        │  本地运行时网站优先读取它；*.github.io 上不读取
        ▼
公开仓库只有代码 + 示范内容（.gitignore 排除 private/）
```

### 部署方式——需要你决定

| 方案 | 真正的访问控制 | 国内打开速度 | 成本 / 门槛 |
| --- | --- | --- | --- |
| A. 私有仓库 + Cloudflare Pages + Cloudflare Access（她用邮箱收验证码进入） | 有 | 不稳定，有时慢 | 免费，需注册 Cloudflare |
| B. 腾讯云 / 阿里云对象存储静态网站 | 无，只靠不可猜的长链接 | 快 | 几元/月；绑自定义域名需备案 |
| C. 不上线：生日当天用你的电脑或 iPad 打开本地版本，或打包文件夹发给她 | 最私密 | 不依赖网络 | 0 |
| D. 当前公开 GitHub Pages | 无 | 一般 | 只适合放 DEMO，**不能放真实素材** |

无论选哪种，`private/` 都不进当前公开仓库。

## 5. 给 Codex 的任务清单（按顺序）

> 开工前先读 `AGENTS.md`、本文件、`docs/CONTENT_GUIDE.md`。不要改动已确定的视觉方向和展厅结构；不要提交 `private/` 下任何文件。

**T1 补全时间线（主要工作量）**
- 依据《我们的故事_时间线与逻辑梳理》在 `private/content.js` 写全部事件，`chapter` 用已有的 4 个篇章 id。
- 照片从 `private/photo-index.json` 按日期 / 事件匹配。每件展品 1–6 张，聊天截图写 `type:'chat'`，拍立得正反面配成一个 `type:'polaroid'`。
- 归档里有大量 `IMG_xxxx 2.JPG` 与 `IMG_xxxx.JPG` 成对的重复副本，只用其中一张。
- 正文只用文档里的原话或忠实改写，**不得编造经历**；英文副标题可以写。
- 重要日子标 `highlight:true`：正式纪念日、博士录取、毕业典礼、一周年、25 岁生日等。
- 有原话的写进 `quote`（拍立得背面文字尤其要保留）。
- 验收：每个篇章都能点开，每件展品照片能加载（控制台无 404）。

**T2 待确认日期**：文档末尾列出的 8 条待核对事项，按你的确认结果处理；未确认的保持文档现有写法，不要自行决定。

**T3 补全地点**：北戴河、长沙、南昌（琥珀园小家）、郑州、北京、哈尔滨、南昌华林、成都、九江吴城、深圳等，每个地点填 `events` 关联事件，`x/y` 只是星图上的摆放位置，大致保留南北东西关系即可，避免光点和地名互相遮挡（手机 360px 宽时检查）。

**T4 终厅**：等你写好信再填 `letter`；在那之前保持占位。

**T5 回归测试**：手机 360 / 390 / 430 宽 + 电脑 1366 / 1920 宽；流程：入口 → 大厅 → 时间长廊（篇章切换、照片滑动、灯箱、拍立得翻面）→ 足迹（光点、互链跳转）→ 终厅（开信、合信）→ 返回；无横向溢出、无控制台错误；开启系统“减弱动态效果”再走一遍。

**T6（内容完成后再做）合并 CSS**：把 `styles.css` + `light-theme.css` + `peony-theme.css` + `exhibits.css` 合并为一个主题文件，删掉被覆盖掉的深色规则；合并前后逐页截图对比，视觉不得变化。

**T7（可选）**：自托管 Noto Serif SC 的子集字体，保证所有设备上字体一致；最后把 `demoMode` 改为 `false`。
